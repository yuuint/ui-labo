# 都道府県 Picker

## 概要

日本の都道府県、またはエリア（地方区分）を**日本地図から選ぶ**入力コンポーネント。
`select` と同じ大きさのフォーム部品で、押すと地図を載せたポップオーバーが開く。
読み（漢字・かな・ローマ字）による絞り込みと、区切り・値の表現・選択単位・選択数の切り替えを持つ。

## データ

### 都道府県マスタ

原本は 2 ファイル。実行時に API を呼ばない（ADR `shared-data-package` / `data-snapshot-from-api` / `supplement-merge`）。

```
packages/data/src/
├── prefectures.api.json         # ynetlabo API のスナップショット。手で編集しない
└── prefectures.supplement.json  # 読み・正式名称。手で編集する
```

| フィールド | 型 | 例 | 所有者 |
|---|---|---|---|
| `code` | string | `"13"` | 導出（`pref_code` の先頭 2 桁） |
| `ynetlaboCode` | string | `"13-TOK"` | API（`pref_code`） |
| `name` | string | `"東京都"` | **補完テーブル** |
| `shortName` | string | `"東京"` | API（`name_jp`） |
| `kana` | string | `"とうきょうと"` | **補完テーブル** |
| `kanaShort` | string | `"とうきょう"` | **補完テーブル** |
| `romaji` | string | `"tokyo"` | 導出（`name` を小文字化） |
| `areaCode` | string | `"3-KTO"` | API（`prefarea_code`） |
| `searchKeys` | string[] | — | 生成（後述） |

補完テーブルのキーは JIS コード。3 フィールドのみを持つ。

```jsonc
{ "13": { "name":"東京都", "kana":"とうきょうと", "kanaShort":"とうきょう" } }
```

### 地図の形状

県境ポリゴンは **Natural Earth**（パブリックドメイン）から生成する（ADR `japan-map-geodata`）。
出典明記も利用報告も不要な出典を選んでいる。ライブラリ利用者に義務が伝播しない。

```
packages/data/
├── src/japan-outline.json     # 簡略化・平滑化・投影済みのパス。sync:geo の生成物
├── scripts/                   # sync:data / sync:geo / build と、その部品
└── dist/                      # build の生成物。手で編集しない
    ├── prefectures.js / .d.ts   # Web
    ├── prefectures.g.dart       # Flutter
    ├── Prefectures.g.swift      # SwiftUI
    └── japan-outline.js         # Web（viewBox とパス）
```

`npm run sync:geo` を明示実行したときだけ配布元から取得し、以下を通して書き出す。
元データ（15MB の shapefile）はコミットしない。

1. `adm0_a3 == "JPN"` の 47 件を抽出する。`iso_3166_2`（`JP-01`〜`JP-47`）の
   数値部が JIS X 0401 の都道府県コードと一致する
2. 本島から 1.15 度以上離れた島と、最大リング面積の 0.7% 未満の島を落とす
3. **穴リング（最大リングと逆向きの輪）を落とし、残るリングの向きを揃える。**
   揃えないと、エリアを 1 つのパスに結合したときに塗りが打ち消し合い、
   エリア選択モードで県の内側に穴が空く
4. Douglas-Peucker（許容 0.024 度）で頂点を減らす
5. Chaikin の角落としを 2 回かけて輪郭を丸める（**堅い直線を避けるため**）
6. Douglas-Peucker（許容 0.0035 度）で直線部の点を間引く
7. cos 37° 補正の正距円筒図法で投影し、`viewBox` 座標へ正規化

結果は 47 件・約 4,500 頂点・約 56KB。各県は `d`（パス）、`b`（外接矩形）、`c`（ラベル位置）を持つ。

### 整合性の保証

合成時に以下を検査し、1 つでも満たさなければ**ビルドを失敗させる**。

1. 補完テーブルのキー集合が、API 応答の JIS コード集合と過不足なく一致する
2. `shortName` が `name` の前方部分である（等しい場合を含む。北海道が該当）
3. `kanaShort` が `kana` の前方部分である（同上）
4. 47 件すべてが 1 つの `areaCode` に属する
5. `japan-outline.json` が 47 件すべてのパスを持つ

検査 1 が、この構成における唯一の実質的なリスク
（API 側の増減に補完側が追随できていない状態）を機械的に捕まえる。

## 契約（プラットフォーム非依存）

### 選択の単位 — `selectionLevel`

| 値 | 選ぶもの | 段階 |
|---|---|---|
| `"prefecture"`（既定） | 都道府県 | 全国 → エリア → その中の県 |
| `"area"` | エリア（地方区分） | 全国のみ。エリアを押した時点で確定 |

`"area"` では**県境を描かない**。エリアを 1 つの面として描き、当たり判定もエリア単位にする。
「ここで県を選ぶのか」と迷わせないため。県名検索も働かないので検索欄を出さない。

### 選択数 — `multiple`

| 値 | 挙動 |
|---|---|
| `false`（既定） | 選ぶと確定してポップオーバーを閉じる |
| `true` | 押すたびに追加・解除。**ポップオーバーは開いたまま** |

`true` のとき下部に「N 件選択中」と **クリア / 完了** を置く。
`true` → `false` に戻したときは先頭 1 件だけを残す。
`selectionLevel` を切り替えたときは値の意味が変わるため**破棄する**。

### 値の表現 — `codeFormat`

内部での同一性判定は常に JIS コード（`"area"` ではエリアキー）で行う。
`codeFormat` は **`value` の受け渡しと変更イベントで使う表現**を決める。入出力で対称。

| 値 | `selectionLevel="prefecture"` | `selectionLevel="area"` |
|---|---|---|
| `"jis"`（既定） | `"13"` | `"kanto"` |
| `"jisNumber"` | `13` | `"kanto"` |
| `"ynetlabo"` | `"13-TOK"` | `"3-KTO"` |
| `"iso"` | `"JP-13"` | `"kanto"` |
| `"name"` | `"東京都"` | `"関東"` |
| `"shortName"` | `"東京"` | `"関東"` |

エリアの `"ynetlabo"` は `grouping="region9"` のときだけ API の `prefarea_code` と一致する。
`"name"` / `"shortName"` は表記揺れに弱い。互換目的でのみ用意する。
**新規実装では `"jis"` を、ynetlabo 自身のアプリからは `"ynetlabo"` を使う。**

`multiple` が真のとき、値は上表の表現の**配列**になる。

### 区切り — `grouping`

| 値 | 区切り | グループ数 |
|---|---|---|
| `"region9"`（既定） | ynetlabo API の地方区分をそのまま使う | 9 |
| `"region8"` | 標準 8 地方区分（沖縄を九州に含める） | 8 |
| `"region11"` | 中部を細分し、三重を東海に移す | 11 |
| `"kana"` | 五十音（あ行〜わ行） | 10 |
| `"none"` | 区切らない | 0 |

既定を `"region9"` としたのは、API のデータをそのまま使う経路に変換を挟まないため。

#### `region9`（既定・API 準拠）

| キー | 表示名 | `areaCode` | コード |
|---|---|---|---|
| `hokkaido` | 北海道 | `1-HKD` | 01 |
| `tohoku` | 東北 | `2-THK` | 02–07 |
| `kanto` | 関東 | `3-KTO` | 08–14 |
| `chubu` | 中部 | `4-CHB` | 15–23 |
| `kinki` | 近畿 | `5-KNK` | 24–30 |
| `chugoku` | 中国 | `6-CGK` | 31–35 |
| `shikoku` | 四国 | `7-SKK` | 36–39 |
| `kyushu` | 九州 | `8-KYS` | 40–46 |
| `okinawa` | 沖縄 | `9-OKA` | 47 |

グループのキーは安定した英字とし、`areaCode` と 1 対 1 に対応させる。
API の `prefarea_code` をそのままキーにしない（API 側の採番変更に引きずられないため）。

#### `region8`

`region9` の `kyushu` と `okinawa` を統合し、表示名を「九州・沖縄」とする。

#### `region11`

`region9` の `chubu`（15–23）を分け、`kinki` から三重県（24）を `tokai` へ移す。
グループの並びはこの順。

| 順 | キー | 表示名 | コード |
|---|---|---|---|
| 1 | `hokkaido` | 北海道 | 01 |
| 2 | `tohoku` | 東北 | 02–07 |
| 3 | `kanto` | 関東 | 08–14 |
| 4 | `hokuriku` | 北陸 | 16–18 |
| 5 | `koshinetsu` | 甲信越 | 15, 19, 20 |
| 6 | `tokai` | 東海 | 21–24 |
| 7 | `kinki` | 近畿 | 25–30 |
| 8 | `chugoku` | 中国 | 31–35 |
| 9 | `shikoku` | 四国 | 36–39 |
| 10 | `kyushu` | 九州 | 40–46 |
| 11 | `okinawa` | 沖縄 | 47 |

`region9` と `region11` で三重県（24）の所属が異なる。**これは意図的**。
区分の流儀そのものを切り替えるパラメータであり、どちらかに寄せない。

### API

| 名前 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `value` | 単数: 上表の表現 \| null / 複数: その配列 | `null` / `[]` | 選択中の値 |
| `selectionLevel` | `"prefecture"` \| `"area"` | `"prefecture"` | 選ぶ単位 |
| `multiple` | boolean | `false` | 複数選択 |
| `codeFormat` | 上表参照 | `"jis"` | `value` と変更イベントの表現 |
| `grouping` | 上表参照 \| カスタム定義 | `"region9"` | 区切り |
| `layout` | `"list"` \| `"map"` | `"map"` | 表示方式 |
| `items` | 都道府県の配列 | 埋め込みスナップショット | データの差し替え |
| `placeholder` | string | `"選択してください"` | 未選択時の表示 |
| `disabled` | boolean | `false` | 操作不可 |
| `required` | boolean | `false` | 未選択を不正とする |
| `invalid` | boolean | `false` | 外部からエラー表示を強制する |
| `display` | `"name"` \| `"shortName"` | `"name"` | トリガへ表示する表記 |
| `searchable` | boolean | `true` | 絞り込み入力を出す（`"area"` では無効） |
| `mode` | `"dropdown"` \| `"inline"` | `"dropdown"` | 表示のしかた |
| `transition` | `"auto"` \| `"fade"` \| `"slide"` \| `"none"` | `"auto"` | 開閉の見せ方（`"inline"` では開閉が無い） |
| `popoverMinWidth` | 長さ | `272px` | ポップオーバー幅の下限 |
| `popoverMaxWidth` | 長さ | `420px` | ポップオーバー幅の上限 |
| `name` | string | — | フォーム送信時のフィールド名（Web のみ） |

`display` は**見た目の表記**、`codeFormat` は**やり取りする値**。両者は独立して指定できる。

イベント: 値が変わったとき `change` 相当を発火し、`codeFormat` に従った値（複数選択では配列）を渡す。
**選択が変わっていない場合は発火しない。**

### 寸法とレスポンシブ

フォーム部品として使われるため、`select` から逸脱しない大きさに収める。

| 対象 | 値 |
|---|---|
| トリガの高さ | 38px（同じフォームの `input` と揃える） |
| ポップオーバーの幅 | **入力欄の幅に追従**。下限・上限で制御する |
| ポップオーバーの幅の下限 | `popoverMinWidth`（既定 272px） |
| ポップオーバーの幅の上限 | `popoverMaxWidth`（既定 420px） |
| 地図の高さの上限 | ビューポート高の 56%、かつ 500px |
| ヘッダのボタン・一覧の行の高さ | タップ領域 44pt 以上 |

ポップオーバーは入力欄と同じ幅を基準にし、**下限と上限で挟む**。
狭いフォームでは下限まで広がり、広いフォームでは上限で止まる。
画面幅が足りないときは `100vw - 24px` を超えない。

下限・上限はオプションで変更できる。地図は幅に合わせて拡縮し、
一覧は幅いっぱいに広がる。

> 幅を固定にすると、狭いフォームでははみ出し、広いフォームでは
> 地図が小さいまま余白だけが増える。地図の読みやすさは面積に直結するため、
> 使える幅は使い切る。

#### 狭い画面（600px 未満）

ポップオーバーをやめ、**画面下部のシート**に切り替える。

| 対象 | 値 |
|---|---|
| シートの幅 | 画面幅いっぱい |
| シートの高さ | 内容に応じる。最大 88vh |
| 地図の高さの上限 | ビューポート高の 44% |
| ボタン・入力欄・一覧の行の高さ | **44px 以上**（タップ領域のガイドラインに合わせる） |

- 背景に暗幕を敷き、押すと閉じる
- ヘッダに閉じるボタン（40 × 40 以上）と、つまみを模した目印を置く
- 開いているあいだは背後のページをスクロールさせない
- 下端は `env(safe-area-inset-bottom)` を確保する
- **ソフトウェアキーボードが出たらシートを持ち上げる。**
  `visualViewport` の高さ変化を見て、隠れる分だけ下端を上げる。
  これをしないと iOS Safari で検索欄がキーボードに隠れる

> 狭い画面でポップオーバーのままにすると、画面下にはみ出し、
> 28px のボタンはタップ領域を満たさず、小さい県は狙えない。
> 実測で確認した（ポップオーバー高 547px）。

トリガには選択値の表示に加えて、**実際に送信される値**を右端に小さく出す。
複数選択のときは件数（例: `3件`）を出す。

### 表示のしかた — `mode`

| 値 | 表示 |
|---|---|
| `"dropdown"`（既定） | トリガを押すとポップオーバー（狭い画面ではシート）が開く |
| `"inline"` | **常に表示されたまま。**トリガも暗幕も持たない |

`"inline"` は、都道府県やエリアの選択そのものが主役の画面のためにある。
フォームの 1 項目としてではなく、画面いっぱいに地図を置いて選ばせたいとき。

- トリガ・暗幕・閉じるボタンを出さない
- 選んでも閉じない。外側を押しても閉じない。`Esc` も閉じない
  （拡大中の `Esc` は全国に戻る。これは残す）
- 幅は置かれた場所に合わせる。`popoverMinWidth` / `popoverMaxWidth` は効かない
- **狭い画面でもシートにしない。** その場に収まったままにする
- 値の受け渡しとフォーム参加は `"dropdown"` と同じ

高さの上限を持つ枠（メニューやドロワー）に埋め込むときは、
地図と一覧の高さを CSS カスタムプロパティで縮める。

| プロパティ | 既定 | 効く場所 |
|---|---|---|
| `--prefecture-picker-map-max-height` | `min(56vh, 500px)` | 地図の高さの上限 |
| `--prefecture-picker-list-max-height` | `236px` | 一覧の高さの上限 |

既定はビューポート基準なので、枠側が `max-height` を持つ場合は
枠の高さから頭・検索欄・フッタ（合わせて約 130px）を引いた値を渡す。

`layout` の切り替え、区切り、複数選択、拡大は `"dropdown"` と同じように働く。

### レイアウト — `layout`

| 値 | 表示 |
|---|---|
| `"map"`（既定） | 日本地図 |
| `"list"` | 区切り付きの一覧 |

`layout="map"` でも、以下のときは `"list"` として描画する。

- `grouping` が `"kana"` / `"none"` / カスタム定義（地理的な区分ではないため）
- `selectionLevel="prefecture"` かつ検索欄に文字が入っている

#### ポップオーバーの構成

```
[トリガ 38px]
┌─ ポップオーバー ───────────────────┐
│ [← 全国][中部]      [地図|リスト][✕] │ ← ヘッダ
│ 検索欄（県選択モードのみ）           │
│ ┌───── 日本地図 ─────┐              │
│ │                    │              │
│ └────────────────────┘              │
│ N 件選択中       [クリア][完了]      │ ← multiple のみ
└──────────────────────────────────────┘
```

**地図の下にラベルを置かない。** 状態と操作の手がかりは**ヘッダに集約する**。
地図の直下に説明を置くと、地図が使える高さが削られ、「見て選ぶ」流れも途切れる。

##### ヘッダのラベル

左端のラベルが、現在の段階とホバー中の対象を兼ねる。

| 状態 | 表示 |
|---|---|
| 全国（地図） | `エリアを選ぶ` |
| 拡大中 | 現在のエリア名（例: `中部`）。左に「← 全国」 |
| 一覧 | `都道府県を選ぶ` / `エリアを選ぶ` |
| ホバー・フォーカス中 | その対象の名前に差し替わる |

ホバーの手がかりを地図の外に出すことで、地図そのものに文字を重ねずに済む。

##### 表示の切り替え

ヘッダ右に **地図 / リスト**の切り替えを置く。`layout` を直接変える。

- 地理的でない区切り（`"kana"` / `"none"` / カスタム）のときは「地図」を**無効化**し、
  理由を添える。黙って効かないボタンにしない
- 切り替えても選択値は保持する。拡大していた場合は全国に戻す

##### 閉じるボタン

**位置を固定する。** ヘッダの内容（戻るボタン・現在地・検索欄の有無）で
動いてはいけない。常にヘッダの右端に置き、他の要素を左に寄せる。

> 検索欄の有無や拡大の段階でヘッダの中身が変わるため、
> 素直に並べると閉じるボタンの位置が毎回ずれる。押し間違いの原因になる。

**地図と一覧は、押せるものを別々に辿って結び付ける。**
どちらも同じ属性で対象を指すため、まとめて拾うと一覧の項目に二重に結び付き、
1 回の操作で 2 回切り替わってしまう（複数選択では見かけ上なにも起きない）。

**地図モードでは地図だけを出す。** 同じ選択肢をボタン列としても並べない。
同じものを 2 通りに並べると縦に伸び、地図の取れる高さが減り、どちらを使えばよいか迷わせる。

テキストで選びたい場合は、ヘッダの切り替えで一覧へ移る。
**選ぶ手段は「地図」か「一覧」のどちらか一方**であり、同時には出さない。

カーソルの変化を唯一の手がかりにしない（タッチでは伝わらないため）。
押せることは、面としての塗り・境界・ヘッダのラベルの変化で伝える。

#### 県選択モード（`selectionLevel="prefecture"`）

1. **全国** — 47 県を描き、エリアごとに塗り分ける。県を押すのではなく**エリアを押す**
2. **拡大** — 押したエリアへ地図がズームし、その県だけが操作対象になる。県名が乗る
3. 県を押すと確定（`multiple` では追加・解除）

- 所属する県が 1 件のエリア（`region9` の北海道・沖縄）は、**エリア押下で即確定**する
- 拡大中に**選択対象でない場所（海・薄いエリア）を押すと全国へ戻る**。閉じない
- ヘッダの「← 全国」でも戻る

#### エリア選択モード（`selectionLevel="area"`）

全国表示のみ。エリアを押した時点で確定（`multiple` では追加・解除）。
拡大の段階を持たない。

### 地図の描画

- 実測の県境ポリゴンを使う（ADR `japan-map-geodata`）。正確な地図ではなく、
  離島を落とし、輪郭を丸めた概略図とする
- **沖縄は本土から離れすぎるため、破線の枠で囲った別枠（インセット）に置く。
  枠の内側全体を当たり判定にする**（図形そのものは小さく、押せないため）
- 面積の小さいエリア（四国・沖縄など）は、図形の外側に透明の余白を足して
  当たり判定を広げる。見た目は変えない
- **選択中のエリアの外周は、控えめな太さと色にする。** 高コントラストの太線で囲うと、
  地図そのものより枠が目立ち、他のエリアが読みにくくなる。
  選択の識別は ✓ の印と塗りの濃さが担うので、枠は輪郭を示す程度でよい
- 県選択モードでは県ごとの図形を描く。エリア選択モードではエリアを 1 面として描き、
  **県境を描かない**。エリア同士の境目だけを縁取りで示す
- エリアの塗りは **半透明にしない。** 不透明な混色（薄い色そのもの）を使う。
  半透明にすると、隣接県の塗りが重なった帯だけ濃くなり、面の中に筋が走る
- 各県の輪郭は独立に簡略化されるため、共有境界がわずかにズレて隙間ができる。
  エリアの塗りを**自色でわずかに太らせて**塞ぐ。塞がないと面の中に海の色が覗く
- エリアの塗り分けは、**隣り合うエリアが明度でも分かれる**順に色を割り当てる
  （色相の差が失われても境目が残るようにするため）

### 開閉のアニメーション — `transition`

開くときと閉じるときの見せ方。**閉じる側も必ずアニメーションさせる**（消え方が唐突だと
「閉じた」のか「壊れた」のか区別がつかない）。

| 値 | ポップオーバー | シート（狭い画面） |
|---|---|---|
| `"auto"`（既定） | フェード（わずかに下から立ち上がる） | **下から現れ、下へ消える** |
| `"fade"` | フェードのみ | フェードのみ |
| `"slide"` | 下から立ち上がる | 下から現れ、下へ消える |
| `"none"` | 即時 | 即時 |

| 対象 | 長さ | 補間 |
|---|---|---|
| ポップオーバー | 0.17 秒 | `cubic-bezier(.22,.7,.3,1)` |
| シート | 0.30 秒 | `cubic-bezier(.32,.72,0,1)` |
| 暗幕 | シートに合わせる | フェード |
| **中身の入れ替えによる高さの変化** | 開閉と同じ | 開閉と同じ |

地図と一覧では高さが大きく違う。切り替えでそのまま入れ替えると跳ねるので、
**高さの変化も補間する**。入れ替え前の高さを測って固定し、入れ替え後の高さへ動かす。

> 遷移しない設定（`"none"` / `prefers-reduced-motion`）では**高さを固定してはいけない**。
> 固定すると遷移の終了が通知されず、その高さのまま張り付く。
> 遷移が完了しなかった場合に備えて、時間切れで解除する保険も要る。

- ポップオーバーは上端を基点に、シートは下端を基点に変形する
- シートは**移動だけ**で、不透明度は変えない。暗幕のフェードが奥行きを担う
- 閉じ切るまで要素を DOM から外さない。**可視性は遷移の終了と同時に切り替える**
  （先に消すと閉じる動きが出ない）
- `prefers-reduced-motion: reduce` のときは `"none"` と同じ扱いにする

#### ズームの遷移

エリア → 県、およびその逆で、拡大・縮小の向きが分かる遷移を入れる。
地図全体を変形させ、タイルや図形を並べ直さない。

- 全国の状態で描画してからレイアウトを確定させ、そのあと目標へ動かす
- 長さ 0.52 秒
- `prefers-reduced-motion: reduce` のときは無効にし、即座に切り替える

> `requestAnimationFrame` で次フレームに切り替える実装は、
> 非表示のタブやバックグラウンドで発火せず遷移が起きない。
> レイアウトを強制的に確定させる方式を使う。

### 状態の表現

**色だけで状態を区別しない。** 塗りの濃さ・縁取りの有無・記号を併用する。

| 状態 | 塗り | 縁取り | 記号 |
|---|---|---|---|
| 通常 | 薄い（50%） | なし | なし |
| ホバー / フォーカス | 濃い（94%） | 細い中間色 | なし |
| 選択中 | 不透明 | 太い高コントラスト色 | ✓ |
| 対象外（拡大中の他エリア） | 20% | なし | なし |

**✓ の印は図形の中心に置く。** 位置は**面積重心**を使い、頂点の平均を使わない。
頂点の平均は、入り組んだ海岸線のように頂点が密な側へ寄ってしまう。
エリアの中心は、所属する県の面積で重み付けして求める。

縁取りは**選択したものの外周だけ**に出す。内側の県境には出さない。
塗りの下に太い縁取りを敷き、上から塗りで覆うことで実現する（ポリゴンの合成計算を要しない）。

**県選択モードでは、強調するのは選択した県だけ。**
その県が属するエリアを縁取ったりしない。
選択が無いときにエリア全体を明るくすることもしない。

一覧表示の選択行には ✓ と太字を付ける。ホバー行は濃い輪郭にする（塗らない）。

### 検索

`searchable` が真かつ `selectionLevel="prefecture"` のとき、入力文字列で絞り込む。

**正規化**（クエリと `searchKeys` の両方に同じ手順を適用する）:

1. Unicode NFKC 正規化（全角英数 → 半角、半角カナ → 全角カナ）
2. 小文字化
3. カタカナ → ひらがな
4. **長音の畳み込み** — 以下を順に適用する
   1. 長音符 `ー` を除去する
   2. お段のかな（`お こ そ と の ほ も よ ろ ご ぞ ど ぼ ぽ ょ`）に続く `う` / `お` を除去する
   3. え段のかな（`え け せ て ね へ め れ げ ぜ で べ ぺ ぇ`）に続く `い` / `え` を除去する
5. 前後の空白を除去

手順 4 は `ー` を除くだけでは足りない。日本語の長音は「とうきょう」（`う`）と
「おおさか」（`お`）で表記が割れるため、`ー` を母音に展開する方式ではどちらかが必ず外れる。
長音を畳んで `ときょ` `おさか` に寄せると、`トーキョー` `とうきょう` `オーサカ` `おおさか`
がすべて同じ形に落ちる。畳み込み後のキーは内部表現であり、画面には表示しない。

**`searchKeys` の構成**（生成スクリプトが上記正規化を適用して出力）:

- `name` / `shortName`（漢字）
- `kana` / `kanaShort`
- `romaji`（ヘボン式。API の `name` 由来）
- `kana` から機械変換したワープロ式ローマ字

ヘボン式とワープロ式を両方入れることで、`fukushima` と `hukusima`、
`chiba` と `tiba` のような表記揺れが自動的に両対応になる。

**照合**: いずれかの `searchKeys` に対する部分一致。前方一致を上位に並べる。

> 検索ロジックを 4 実装で個別に書くと必ずズレる。
> ローマ字変換とかな正規化は生成スクリプト側に寄せ、
> 各実装は「正規化済み文字列の部分一致」だけを行う。

### 使用トークン

component 層に `prefecture-picker.*` を定義する（spec `design-tokens` の 3 層構造に従う）。
semantic 層のみを参照し、primitive を直接参照しない。

- トリガ: 背景 / 枠線 / 文字色（各状態ぶん）
- ポップオーバー: 背景 / 影 / 角丸
- 海（地図の余白）: 背景色
- エリアの塗り: 最大 11 色。明度が交互になる並び
- 県境・エリア境の線: 色 / 太さ
- 選択・ホバーの縁取り: 色 / 太さ
- ヘッダ: 背景 / 区切り線 / 切り替えの選択中背景
- 一覧の行: 背景（default / hover / selected）/ 文字色

### アクセシビリティ

トリガは `aria-haspopup="dialog"`。開いた中身はダイアログとし、現在の段階を示すラベルを持つ。

- 地図の各図形はボタンとし、キーボードでも辿れる
- 選択状態は `aria-pressed`（複数選択）または `aria-current`（単数選択）で示す
- 対象外の図形は支援技術に露出させない
- 未選択かつ `required` の場合、`aria-invalid` を立てる

**キーボード操作**:

| キー | 動作 |
|---|---|
| `Tab` | ヘッダ・地図の図形・一覧の行を順に辿る |
| `Enter` / `Space` | 押す |
| `Esc` | 拡大中はエリア選択へ戻る。全国では閉じる |
| 文字入力 | `searchable` が真なら絞り込み（一時的に list 表示へ） |

### Web の実装方式

- **属性とプロパティのどちらから値を渡しても同じに働く。**
  フレームワーク（Vue / React など）は値を**プロパティ**で渡すため、
  属性の変化だけを見ていると取りこぼす。変更の経路を 1 か所に集約する

- **Shadow DOM を使う。** 外部からの意図しないスタイル上書きを防ぐ。
  トークンは CSS カスタムプロパティなので shadow 境界を越えて継承され、
  テーマの切り替えはそのまま効く
- **フォーム参加は `ElementInternals`（`formAssociated`）で行う。**
  隠し input を置かない。複数選択のとき同名で複数の値を送るのが素直に書け、
  `setValidity` で `required` の検証も標準の仕組みに乗る
- **初回の描画は同期で行う。** 次のフレームに任せると、非表示タブや
  バックグラウンドでは `requestAnimationFrame` が発火せず一度も描画されない。
  2 回目以降だけ 1 フレームにまとめる

## プラットフォーム差異

意図的に揃えない点のみを記す。

| プラットフォーム | 差異 | 理由 |
|---|---|---|
| 全般 | `value` の型は `codeFormat` に対応する素の型。enum は補助 API として別途公開する | `codeFormat` で表現が変わる以上、値の型を固定できない |
| Web | `grouping` のカスタム定義は属性ではなくプロパティで渡す | HTML 属性は文字列しか取れない |
| Web | `name` 指定時、`ElementInternals` でフォーム送信に参加する。複数選択では同名で複数送る | 素の HTML フォームから使えることを保証するため |
| Web / Vue | トリガ直下にポップオーバーを開く | 画面下端に近い場合は上方向へ反転する |
| Flutter | 画面幅が 600 未満のとき modal bottom sheet、以上でポップオーバー | モバイルでのポップオーバーは片手操作で届きにくい |
| SwiftUI | sheet 上に地図を置く | — |
| SwiftUI | **wheel picker は採用しない** | 47 件はホイールには多すぎ、検索も併用できない |

## 対象外

以下は本 spec では扱わない。必要になった時点で別 spec を起こす。

- 市区町村・住所の入力
- 日本語以外の UI 表記（都道府県名の英語表記を含む）
- 「海外」「不明」などの選択肢の追加
- 正確な地図（県境の忠実な再現、面積の保持、離島の網羅）
- 地図の回転・任意倍率のズーム・パン
