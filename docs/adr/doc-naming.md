# spec と ADR は通し番号を持たず、物理名で識別する

## 背景

当初は `0010-prefecture-picker.md` のような通し番号つきの命名を採り、
本文でも「spec 0010」「ADR 0005」と番号で参照していた。

運用してみたところ、会話でも本文でも**番号だけが独り歩きし、
何の仕様なのかがその場で分からない**という問題が出た。
「ADR 0005 に従って」と書かれていても、開いてみるまで内容が推測できない。

## 決定

- ファイル名は **kebab-case の物理名のみ**とする（`prefecture-picker.md`、`monorepo.md`）
- frontmatter は `id` ではなく `name` を持ち、値はファイル名と一致させる
- 本文からの参照は ``spec `prefecture-picker` `` / ``ADR `japan-map-geodata` `` と書く
- 順序は `date` で表す。一覧は日付順に並べる

## 理由

- **参照した瞬間に中身が分かる。** これが番号にできないこと。
- 番号は「あとから中間に差し込めない」「欠番の意味を説明できない」という運用コストを
  持つ割に、得られるのは順序だけ。順序は `date` で足りる。
- ADR の置換関係（廃止 → 新しい決定）も、番号ではなく名前で指せば十分たどれる。
  むしろ ``ADR `japan-map-geodata` で置換`` のほうが番号より情報量が多い。
- 参照元のリンク切れは、ファイル名を変えなければ起きない。
  番号の付け替えより名前の安定性のほうが守りやすい。

## 影響とトレードオフ

- **`spec-driven-dev` スキルが定める `NNNN-<feature>.md` 形式から意図的に外れる。**
  スキルの番号規約（欠番可・再利用不可）は本リポジトリでは適用しない。
  この差分を知らずにスキルどおり番号を振ると混在するため、
  両ディレクトリの README に命名規約を明記する。
- 一覧の並び順が日付依存になるため、README の表を更新し忘れると順序が崩れる。
  新規追加時に README を更新する運用は番号方式と変わらない。
- 名前の重複は許されない。機能領域の切り方が曖昧だと命名で詰まるが、
  それは spec の粒度が曖昧であることの兆候なので、詰まった時点で見直す。

## 再検討の条件

- 同一ディレクトリの文書が 50 を超え、名前だけでは探せなくなった場合。
  カテゴリごとのサブディレクトリを検討する（番号には戻さない）。
- ADR の置換の連鎖が 3 段以上になり、時系列の追跡が名前だけでは苦しくなった場合。
