# マスタデータは ynetlabo API のビルド時スナップショットを原本とする

## 背景

ADR `shared-data-package` で `packages/data` にマスタデータを置き、コード生成で 4 実装へ配ることを決めた。
ただし「その JSON をどこから得るか」は決めていなかった。暗黙に手書きを想定していた。

都道府県マスタは ynetlabo API が提供する。同じデータを本リポジトリで手書きすると、
API 側と本リポジトリで別々に育ち、いずれ食い違う。

一方で、コンポーネントが実行時に API を叩くことは ADR `shared-data-package` で明確に捨てている
（オフライン動作を失うため）。

## 決定

**取得はビルド時、埋め込みは固定値。** 実行時のネットワークアクセスは行わない。

1. `npm run sync:data` を明示的に実行したときのみ ynetlabo API を呼ぶ。
2. 応答を `packages/data/src/prefectures.api.json` に書き出し、**コミットする**。
   併せて `_meta` に取得元 URL と取得日時を記録する。
3. 通常のビルド（`npm run build`）はコミット済みスナップショットのみを読む。
   **API には触れない。**
4. 生成された TypeScript / Dart / Swift 定数がコンポーネントの既定データになる。

### 取得元

| 項目 | 内容 |
|---|---|
| 都道府県 | `GET https://api.ynetlabo.net/com/prefs` |
| 地方区分 | `GET https://api.ynetlabo.net/com/pref_areas` |
| 認証 | 不要（`/com/*` は無認証で取得可能） |

`pref_areas` は 9 区分（北海道 / 東北 / 関東 / 中部 / 近畿 / 中国 / 四国 / 九州 / 沖縄）を返し、
各区分に属する都道府県を含む。**地方区分は API 側が持つ**ため、
本リポジトリで区分の割り当てを定義しない。

### 応答が持たないもの

API は読み（かな）と正式名称（「東京都」）を持たない。
これらの補完方法は ADR `supplement-merge` で定める。

## 理由

- **通常ビルドを外部依存から切り離すため。** 毎ビルドで API を叩くと、
  オフラインでビルドできず、API 障害が CI 障害になり、
  Flutter / Swift のビルドまで巻き込まれる。取得と利用を分ければこれが起きない。
- **データの変更がレビュー可能になる。** スナップショットをコミットするので、
  `sync:data` の結果は差分として PR に現れる。
  「知らないうちに都道府県名が変わっていた」という事故を防げる。
  47 件のマスタは実質不変なので、差分が出ること自体が異常のシグナルになる。
- **ライブラリ利用者に API の存在を意識させないため。** 埋め込み固定値なので、
  利用者は API キーもネットワークも不要で、npm / pub / SPM から入れれば動く。
- **`/com/*` が無認証なので、CI に秘密情報を置かずに済む。**
  ただし ui-labo のビルドは API を呼ばないため、CI で `sync:data` を実行する必要自体がない。
- API 側が地方区分を持っているため、区分の定義を本リポジトリに複製せずに済む。

## 影響とトレードオフ

- API 側でデータが更新されても、`sync:data` を実行してリリースするまで反映されない。
  都道府県マスタでは実害がないが、**更新頻度の高いデータには本方式を使えない**。
- API の応答形式が変わると `sync:data` が壊れる。取得直後にスキーマ検証を行い、
  壊れたデータをコミットしないようにする。
- ynetlabo API が将来停止しても、スナップショットがコミット済みのため
  ライブラリのビルドと配布は継続できる。
- 捨てた選択肢: 手書き JSON。原本が二重化するため。
- 捨てた選択肢: git submodule で API 側リポジトリを参照。
  4 ツールチェーンのビルドに submodule 初期化の手順が増える割に、
  得られるのはスナップショットと同じ「固定された値」でしかない。

## 再検討の条件

- API 側のデータ更新が年 1 回を超える頻度になり、
  手動 `sync:data` の運用が追いつかなくなった場合（定期実行の CI ジョブを検討する）。
- `/com/*` に認証が必要になった場合。`sync:data` の実行者と鍵の置き場所を決め直す。
- 実行時に最新値が必要な種類のデータを扱う要件が出た場合。
  そのデータは本方式の対象外とし、新規 ADR で決める。
- スナップショットが 1MB を超えた場合。リポジトリに置く前提を見直す。

## 関連

- ADR `shared-data-package`（共有マスタデータの置き場所）— 本 ADR はこれを置き換えず、入手元を追加で定める
- ADR `supplement-merge`（API が持たないフィールドの補完）
- spec `prefecture-picker`（都道府県 Picker）
